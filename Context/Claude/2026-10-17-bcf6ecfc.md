- No argument = default to `1d` (last 24 hours)
- `--pr` flag = format output as a PR description instead of a standup bullet list

## Required Workflow

1. Run `git log --oneline --since="<window>"` to get commits in scope.
2. If no commits are found, say so and stop.
3. Run `git diff <oldest-commit-in-range>^..HEAD --stat` to get a file-level overview.
4. For any files that changed significantly (>20 lines), read the relevant diff sections to understand *what* changed, not just *that* it changed.
5. Group changes into logical themes (e.g. "Auth refactor", "UI tweaks", "Bug fixes").
6. Write the summary in the appropriate format (see Output Rules).

## Output Rules

### Standup format (default)

A short bulleted list, past tense, one bullet per logical theme. Lead with the most impactful change. No filler words. Example:

```
Yesterday:
- Refactored auth middleware to remove session-token storage (compliance)
- Fixed null-pointer in School.tsx when user has no enrollment
- Added unit tests for the new grade export endpoint

Today:
- PR review for #412
- Start on STD-890 (bulk import flow)
```

If today's plans cannot be inferred from context, omit the "Today:" section and note that you only have commit history.

### PR format (`--pr` flag)

A structured PR body:

```markdown
## Summary
<2-4 bullet points of what changed and why>

## Changes
<file-level breakdown grouped by concern>

## Test plan
<what to check manually or in CI>
```

## Constraints

- Do not invent work that is not in the commits or diff.
- If commits are cryptic (e.g. "wip", "fix"), read the diff to infer intent rather than echoing the commit message.
- Keep the total output under 200 words unless `--pr` flag is set.
- Never include secrets, tokens, or credentials that appear in diffs.
